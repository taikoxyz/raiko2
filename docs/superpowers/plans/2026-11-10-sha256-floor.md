# SHA256 fixed-floor recalibration

The user approved recalibrating the PC02 fixed floor after tracing its provenance.
The existing 20M PGU floor was a declared conservative Mainnet coverage tariff;
the independent 42 PGU/native-gas structural coefficient has paired-fit support.
Keep that coefficient and every other pricing component unchanged.

## Approach

Use the existing `max(constant, linear)` representation. Derive a single smaller
constant from retained same-program observations. Preserve the accepted slope,
structural slope, dispatch, memory, resources, startup and proposal terms.
Do not introduce a new curve, remove safeguards, adjust a limit, or rebuild a guest.

For each same-length/pattern pair, divide the positive whole-proposal PGU increment
by the extra number of successful SHA calls. Include all loop/check scaffolding.
Require `max(C, 42*native_gas) >= 5/4 * incremental_PGU_per_call`; choose the smallest
nonnegative C satisfying all pairs and round upwards to 64 PGU. Observed absolute
startup gaps remain in the reported node/proposal metrics.

The 36 retained observations cover six lengths, two patterns and zero/single/full
counts. They are already opened development evidence, not a fresh holdout. The four
recent small-input observations are additional opened regression checks. No new
SP1 executions are needed for this bounded change. Padding boundaries, other
messages and production program parity remain explicit coverage limitations.

1. Authenticate original actual/input/native identities and PGU normalization;
   independently recompute the paired envelope and exact candidate.
2. Add a deterministic Reth successor with a pinned parent/evidence artifact,
   regression tests for scope, envelope and invalid evidence, and regenerated Rust.
   Verify that only the PC02 accepted constant changes numerically.
3. Build one offline host quote binary from immutable source copies using the
   shared Cargo target. Keep native, observer, ELF and SDK unchanged.
4. Requote the 36 old SHA inputs and four recent small-input inputs; retain current
   parent and candidate reports, exact per-block node sums, complete proposal totals,
   actual PGU, controls and signed differences. Check unrelated retained pressure
   cases and the historical Mainnet panel for any changed protection or quote.
5. Obtain independent complete-diff review and independent behavioral verification;
   investigate every material finding. Update research/usage documentation and the
   pending PRs only after focused tests pass. Preserve Draft/do-not-merge state.

## Verification and limitations

Run Python successor/generator tests, generator checks, focused Rust pricing tests,
formatting and strict clippy for the touched integration. Do not call a whole-block
quote a SHA-only cost, use Unzen score as PGU, infer global usage frequency from a
synthetic corpus, or describe finite empirical coverage as a universal bound.
SHA256 precompile0x02 and EVM KECCAK256 opcode0x20 remain distinct.

No merge, deployment, production limit, collector pin, SDK or guest change is in scope.
