## Approach

Use SDK6.3's public typed `SplicingVM::execute_instruction()` to inspect selected historical registers before and after actual guest instructions. Its sequential immutable trace oracle supplies historical values. CoreVM has no arbitrary historical RAM; do not read the native mmap or claim a whole-table snapshot. No process suspension, private opcode-dispatch copy, saved full trace or guest build is needed.

Keep the existing canonical GasVM computation as the source of aggregate gas and public values. Add optional observation after each ordinary held native chunk, then release it. Both consumers borrow the same raw trace; do not copy its full payload. The producer keeps `is_debug=false`, gas trace threshold134217728 memory entries, two slots, the same memory limit and canonical executor options. Diagnostic replay adds host work; its timing is not prover/GPU time or the original canonical measurement. A new executable has its own identity.

Alternatives considered: the earlier stopped-child/latest-boundary snapshot requires ownership/lifetime synchronization and may miss the narrow PC window; full TracingVM records retain unnecessary events. Public per-instruction splicing supplies the needed actually-loaded values with less machinery. Unread memory and complete table occupancy remain unknown.

## Interface and bounds

Extend the existing standalone `bin/zkgas/sp1-estimator` with optional `--observation-plan PATH`. Omitted means the existing argument contract, canonical runner/options, input framing and report shape remain unchanged. One supplied plan adds an `observation` object to the report; it never changes the meaning of existing gas fields. Reuse one authoritative canonical execution loop/options function and the existing bounded IO/resource receipts.

Strict JSON plan: exactly `schema_version:1`, `elf_sha256`, `instruction_limit`, `watches`. A watch has exactly `label`, `pc`, `registers`, `sample_limit`, and optional `skip_hits` default0. Label is a unique ASCII identifier1..64 bytes; pc is lowercase `0x` plus16 hex digits and must identify an executable instruction in the supplied Program. Registers are distinct integer indices0..31, nonempty. Reject duplicate PC/label, unknown/duplicate fields, bool/domain errors, empty watches, more than64 watches, more than1024 samples per watch or more than2048 samples across the plan. File read is bounded at64KiB before parsing. Instruction limit is1..1,000,000,000. Plan ELF SHA must exactly match the actual file. Validate before native runner/resource creation.

Count every matching PC with checked counters. Retain only the first `sample_limit` matches after `skip_hits`; counters still include skipped and unsampled matches. Each sample has historical PC, clocks and the requested register values before/after the SDK step. Keep plan hash, selected register indices, total processed instructions and completion status. At the instruction limit, stop diagnostic replay and mark it incomplete while canonical estimation continues; never report absent samples as a complete map/seed observation. Preserve trace-end/halt/read-cursor continuity; do not step an exhausted trace. If diagnostic replay fails, expose a bounded error/incomplete status and finish canonical execution safely where possible, without silently claiming complete observations.

No all-instruction event collection, unbounded vectors, `ExecutionRecord` history, arbitrary native-memory reads or diagnostic data in the input. Structured observation output is at most4MiB; check a conservative prelaunch bound and the final encoded size. Existing 64MiB input and canonical output/resource contracts remain. External guards retain6GiB sampled tree PSS,600s runtime,16MiB logs and192MiB growing stage. No caps increase.
