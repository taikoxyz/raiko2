## Exact host debug encoding and lazy snapshot rule

Per-user hash-input debug commitment is
`SHA256(concat(owner_address20 || index_BE8 || offset_BE8 || length_BE8 || SHA256(message)32))`;
R0 commits empty bytes. Counter commitment is
`SHA256(concat(counter_BE8 for observed loop entries 0..R inclusive))`, excluding
other reads. Keep at most min(R,8) distinct sorted first4/last4 sampled indices.
Opaque tokens capture immutable input bytes at issue. Reads, partial writes,
feedback, arithmetic and branch consumers materialize the actual reference hash;
only a provable full overwrite can discard an unread token. The branchless
KECCAK/PUSH3(32)/MSTORE sequence may discard the previous output token before
capturing its replacement, retaining one pending input; those opcodes still
execute and are independently gas/count accounted. Later mutation of the original
input cannot alter a token's snapshot. Metadata `expected_last_nonce_word_hex`
describes the backing payload word, including L0, not empty-hash bytes/uniqueness.
