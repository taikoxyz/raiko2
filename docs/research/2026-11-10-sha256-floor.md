# SHA256 fixed-floor recalibration

The candidate now prices SHA256 precompile `0x02` as `max(81024, 42 * native_gas)`
PGU per call, with other dispatch, wrapper, memory and resource charges unchanged.
Only its accepted fixed constant changes. The previous 20M minimum was a declared
conservative Mainnet coverage tariff; it was not a measured small-input SHA cost.
The existing 42 PGU/native-gas structural slope remains intact.

This is SHA256, separate from KECCAK256/EVM opcode `0x20`. Neither generic hash usage
nor aggregate guest SHA syscalls establishes this precompile's frequency.

## Target and derivation

Reth commit `b246ae8157045f36b68b57961da79bb66c9a0d0a` contains model
`e8e574db50607857daadfd79f24e2cd6773177f6b46e4ee950f168379b4cab57`, derived from parent
`c0877d65a0b5fac178342645b5689001e0801718fe1dae0150c59c39ee1c15c1`.
The [model documentation](https://github.com/taikoxyz/alethia-reth/blob/b246ae8157045f36b68b57961da79bb66c9a0d0a/docs/zk-gas-pricing-model.md#candidate-sha256-fixed-floor)
and its deterministic successor retain the exact endpoint facts and generation rules.

The 36 retained observations use the same b76 ELF and CPU SDK6.3 gas estimator as
the earlier [bulk](2026-11-04-sha256-bulk.md) and
[linear-regime](2026-11-04-sha256-linear-regime.md) experiments. They cover two content
schedules, six lengths and zero/single/full counts, with two users. The four recent
small-input regressions are additional already-opened observations. No observation
is described as an unopened holdout, and no new SP1 execution was performed.

For every same-length/pattern count pair, require:

```text
max(C, 42 * native_gas) >= (5/4) * max(0, delta_whole_proposal_PGU / extra_SHA_calls)
```

Take the smallest nonnegative C satisfying all 36 pairs and round upward to64 PGU.
No loop, check, wrapper, memory or scaffold cost is subtracted. These contrasts
remain whole-proposal diagnostics rather than isolated SHA measurements.

## Historical price sensitivity

The retained50 Mainnet proposals /9,600 blocks use unchanged canonical inputs.
Sixteen blocks across13 proposals have lower node prices. Literal node totals fall
from86,990,786,811 to83,803,750,651 PGU, a3,187,036,160 reduction (about3.66%). All
Unzen values and unrelated selectors remain unchanged.

Those16 blocks establish actual historical impact of the floor. They do not count
every SHA or KECCAK invocation: the retained quote format has no per-route counters.
Historical actuals from the older program were deliberately not consumed, so this
panel is price sensitivity rather than a PGU-accuracy result.

## Reproduction and limits

The [Atlas fixture release](https://github.com/taikoxyz/raiko2-atlas/releases/tag/fixture-unzen-sha256-floor-v1)
contains40 canonical inputs, original raw native/SP1 reports,80 parent/candidate
quotes and explicit derived standard observation/quote views. Original report bytes
remain unchanged. Two optional derived analyses containing local paths are excluded
with original-hash omission receipts. The companion
[cap fixture](https://github.com/taikoxyz/raiko2-atlas/releases/tag/fixture-unzen-cap-frontier-v1)
retains the earlier pressure and historical inputs.

After verifying and extracting the SHA fixture, existing `zkgas-quote`,
`zkgas-compare`, and `zkgas-report` consume its standard manifests and profiles.
The fixture README gives both archived-comparison and fresh-quote commands. One
independent guarded40-input native replay and subsequent compare/report succeeded.
Original ELF/observer binaries are identified by hash and are additional requirements
for rerunning SP1 observations; they are not bundled as execution tools in Atlas.

Reth verification passed72 Python tests, generator checks,284 unit tests and5 doc
tests. Raiko passed315 focused host tests, strict focused clippy, formatting and full
locked metadata resolution for the workspace and three guest manifests. The real
fixture golden drops by exactly10 ×(20M−81,024)=199,189,760 PGU. Independent code,
dependency, raw-data and consumer verification passed. Reth strict clippy still sees
two verified pre-existing warnings, and `just clippy` is blocked during rustup setup
by an EPERM error. Full workspace/guest/SDK builds were outside this host-only change.

The b76/SDK6.3 observations and finite old/current observer parity do not attest a
current production program, GPU throughput or universal upper bound. SHA padding
boundaries, arbitrary messages and a future production-ELF promotion lane remain
coverage limits. Guest dependency locks were aligned without rebuilding guest ELFs
or SDKs. Collector pins, deployment and consensus modes stay unchanged. Keep the
future-fork PRs Draft / do-not-merge.
